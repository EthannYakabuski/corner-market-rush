## Test configuration and Google Play Games IDs

`platform/config.json` is intentionally committed with Google sample ad IDs, `play_games.enabled=false`, a blank `game_id`, and blank values for every symbolic achievement and leaderboard key. No production backend is configured. `docs/PLATFORM_CATALOG.md` maps each actual catalog key/title/description to its icon; `game/catalog.json` is the source of truth. Enter the matching Google Play Console achievement/leaderboard ID as the value of its key in `play_games.achievements` / `play_games.leaderboards`. Keep the keys unchanged. Boards submit higher-is-better integers, with the game's documented assisted-score rules.

Set the real numeric PGS game ID in **both** `platform/config.json` -> `play_games.game_id` and `export_presets.cfg` -> Android `godot_play_game_services/game_id` (currently the non-production sentinel `"0"`). Configure package/signing-certificate fingerprints, OAuth/test accounts, achievement types and higher-is-better boards in Play Console; then enable `play_games.enabled` only for a deliberately configured test build. Local progress and pending submissions survive unavailable sign-in; this adapter does not implement cloud saves. Production account/linkage/achievement/leaderboard behavior needs owner/device validation.

## AdMob App ID, units, consent and testing

The Android **manifest App ID** comes from `project.godot` -> `[admob] general/android/app_id`. Changing only JSON does not change the manifest. Set the same intended App ID in `platform/config.json` -> `admob.app_id` for consistent metadata. An App ID uses `~`; ad unit IDs use `/`. The committed sample App ID is `ca-app-pub-3940256099942544~3347511713`; Android banner/interstitial/rewarded sample units are `ca-app-pub-3940256099942544/6300978111`, `/1033173712`, and `/5224354917` respectively. See [Google's test-ad instructions](https://developers.google.com/admob/android/test-ads).

The full Godot setting key is `admob/general/android/app_id`; in the text file it is `[admob]` followed by `general/android/app_id="..."`. With the sample App ID, Godot may omit that line and the entire empty section after an editor/headless import: Poing registers the sample as the initial/default value, and Godot does not serialize values equal to their defaults. This is expected normalization, not evidence that the manifest App ID is missing. The Android exporter reads that exact key and falls back to the same sample constant if absent. A different production App ID entered at the correct key remains an explicit setting. See [Godot's default-value saving behavior](https://docs.godotengine.org/en/4.5/classes/class_projectsettings.html#class-projectsettings-method-set-initial-value).

For release/test verification, inspect the generated Android manifest's `com.google.android.gms.ads.APPLICATION_ID` and confirm it matches the intended JSON metadata. A source check must evaluate the correct setting/default/exporter path, not require a redundant sample-value line to survive import. Do not invent another key, modify plugin defaults merely to force serialization, or treat JSON alone as the manifest configuration.

`admob.test_mode` changes status wording; **it does not turn production ad requests into test requests or register a test device**. Keep sample units for development, or separately configure verified test-device requests before exercising real unit IDs. Do not tap live production ads during QA. Consent/UMP and privacy options are wired through the plugin; the owner must configure actual app messages, legal/privacy URLs, age/audience treatment and jurisdiction requirements. `tag_for_under_age_of_consent=false` is the current placeholder, not an audience/legal decision.

Menu banners reserve their measured native height plus safe inset. Live gameplay hides the banner. The game freezes simulation during pending native reward requests, fullscreen ads, app background and its explicit Resume gate. A reward may be earned while an endcard is still open: the game may grant it once to the matching current round but must stay paused until a visible return/resume flow. A closed, failed, unavailable or orphaned request must not grant a benefit. Web/editor fallback returns false; no simulated rewarded entitlement. See `platform/INTEGRATION.md` for the exact API and test boundaries.

## Build, test and release limits

`export_presets.cfg` has Android Gradle/test and single-threaded Web presets. Android minimum API **24** and target API **35** are the current preset settings; this is **not a claim of current Google Play release eligibility**. Do not silently call the test APK a production release. The Android preset includes ARM64, x86 and x86_64; the validator checks the built bundle. There are no Windows distributions. Release signing keys/passwords belong outside Git; configure the owner's signing/build environment privately rather than committing them into presets.

Root coordinates local imports, engine runs, heavy exports and the single native emulator. No engine/device acceptance is implied by this setup document. `.github/workflows/build.yml` installs checksum-pinned Godot/templates, imports, runs the service smoke test, runs every discovered top-level `tests/test_*.gd`, `tests/*_test.gd` or `tests/smoke.gd`, builds an Android debug AAB and single-threaded Web, and attaches license notices. Strict error/leak checks remain enabled. Each test gets a separate `XDG_DATA_HOME` on hosted Linux. Windows tests must likewise use unique process-scoped `APPDATA` and `LOCALAPPDATA` directories, restore the calling environment afterwards, and use `-- --qa-isolated` for game tests. Do not run smoke tests against real profiles. No Pages hosting is enabled.

Passing source tests/hosted builds do not establish native gameplay, SDK reward callbacks, device sound, Web interactivity or production services. Record the exact source commit, APK/Web hashes, native core-loop/save/Back/offline/reward/lifecycle evidence and six genuine screenshots for phone, 7-inch and 10-inch profiles in the handoff. Preserve original tested APKs and distinguish any CI artifacts/rebuilds. Current native acceptance is tracked in the handoff, not inferred here.
